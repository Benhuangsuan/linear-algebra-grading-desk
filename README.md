# 线性代数作业批改平台 · 2.11.0

供助教在 Windows 本机使用的非官方评分辅助工具。支持课程与作业管理、PDF 上传和预览、纯人工评分，以及按所选学生进行 DeepSeek / Qwen 视觉初评。AI 建议须人工复核、确认后才作为最终成绩导出。

完整操作说明见 **[助教本地部署与使用指南](docs/助教本地部署与使用指南.md)**。

2.11.0 按文件保留参考答案草稿，支持跨任务免费合并、失败文件单独恢复或重试，以及保留历史版本的重新整理。已有题目、人工规则和历史成绩不会自动覆盖；上传和打开页面均不会收费。

当前为本地待审核版本，尚未合并或发布；GitHub 已发布稳定版本仍为 v2.8.0。本轮变化见 [2.11.0 修改说明](docs/releases/v2.11.0.md)。

## 从零启动

要求 Node.js **24.13.0 或更新的兼容版本**；已在 Windows、Node.js 24.19.0 / npm 11.17.0 验证。安装依赖需要联网；本地运行无需数据库软件、Docker、Python 或 LibreOffice。

从本仓库下载或克隆源码后，在含 `package.json` 的目录打开 PowerShell：

```powershell
git clone https://github.com/Benhuangsuan/linear-algebra-grading-desk.git
cd linear-algebra-grading-desk
npm.cmd ci
npm.cmd run build
npm.cmd start
```

浏览器打开 <http://127.0.0.1:3000>。保持终端运行，按 `Ctrl+C` 停止；以后回到同一目录运行 `npm.cmd start`。源码更新后重新安装依赖、构建。服务只监听 `127.0.0.1`，适用于单人本机使用。

**无需 API Key 即可使用人工评分。** 初次启动为空库；请自行创建课程、作业及参考材料。公开源码不附学生作业、教材答案或发布者的数据。

## 日常流程

1. 创建课程与作业，在「作业设置」上传自己的参考 PDF，整理并核对题号、评分规则与小问，保存设置。
2. 大题下管理小问：判断题按独立命题计分，解答题默认整题；仅明确独立的小题分别计分。自动整理结果需要你检查，扫描件及排版异常须人工补录、校对。
3. 上传学生 PDF，核对姓名与学号。支持每次最多 50 份、单份 30 MB、1～100 页；不接受加密 PDF。
4. 不使用 AI 时，在学生行的更多菜单进入「人工评分」。AI 操作暂不可用时，弹窗会说明原因，并引导校对题目、选择学生或配置服务。
5. 按需配置真实 AI，勾选指定学生，核对单元、传输授权和预算后预估、启动。先独立人工批改至少两份代表样本，再逐单元对照，决定是否扩大范围。
6. 每人一行，正确题默认隐藏，扣分点折叠。打开原稿，复核全部扣分及不确定项，修改、确认，导出「姓名」「成绩」两列 CSV。

系统默认建议为满分 10、奇数题检查完成、偶数题检查正确性；漏做默认扣 0.2、错误默认扣 0.1。参考材料明确要求“所有题目均需批改”时，新候选包括奇数题在内都检查正确性；已有题目的人工配置保持原样。请按实际教师要求调整并确认。评分由后端根据规则快照计算，已有成绩不因规则变化自动重算；已确认结果须明确重开审核。

「未批改」包含无正式结果的上传、历史模拟结果、未完成的人工评分和失败记录；有效 AI 初评或完整人工评分即使待确认，也不再参与普通 AI 选择。需要重批时使用明确的重新批改入口。

新建人工评分和模拟评分与 AI 一样使用已核对的实际计分题目：独立 a、b 各漏做默认扣0.2，共扣0.4，CSV 为 `9.6，漏2题`；每个单元做错默认只扣一次0.1。解答题默认整题，仅检查完成的题有实质尝试即不扣分。历史整题评分继续按原快照读取；需要改为当前小问评分时，从“修改评分”明确选择“按当前题目重新人工评分”。这会重新录入本份所有题目，原记录保存在修订记录，不调用 AI。

## 可选的真实 AI

### 参考答案整理与图形校对

上传只保存文件，不自动整理或调用AI。「整理参考答案」默认选中“AI 识别（可能收费）”，也可切换“免费自动整理”或“按文字整理（免费）”。免费方式只在本机处理。三种结果都先检查当前、新增、重合题目、检查方式与来源，再采用并保存设置。材料只列题号的完成性题保留，无需编造参考解。

作业范围可自由填写中文，PDF 的小节归属以正文标题、文件名及人工校对为准。“补充章第N节”与教材小节分别管理；同节讲义题、附加题即使题号相同也分别保存，可在调整题目时修改“小节”和“题组”。上传后未整理成功的文件会保留，后续可直接点击“整理题目清单”，检查采用后保存，无需重复上传；启动不会自动改写旧作业。

在题目编辑窗口展开「题目对应的参考答案页面」。上方显示已有参考页，下方用于添加或更换；选择文件后，还要点击对应操作按钮。“应用调整”只更新当前清单，“保存设置”才保存到本机。跨小节参考须明确确认。原成绩、历史快照和费用不变，公式排版以原 PDF 为准。

AI方式可勾选多份参考PDF，自动识别所选文件全部原页，不需要手填页码。只设“本次识别总预算”（默认2元），先预估，再点击“开始 AI 整理”明确授权传输和费用。后台逐文件处理，较长文件按最多四个原页、相邻重叠一页分批，来源仍按原页记录；累计费用或预留超预算时不再请求。每次输出有上限，失败不自动重试；可以取消后续识别。进度、费用与待确认草稿保存本机，刷新或中断不自动续发收费请求。参考材料发现明显身份信息时须先处理；学生作业批改的隐私复选框不变。

每份文件完成后立即保留草稿；即使其他文件失败，也可“查看已识别结果”或跨任务“合并查看已有结果”，检查采用后仍需“保存设置”。历史版本可分别查看；重试仅处理该文件，尽量复用已通过的分页。已有原响应可免费复验，旧版未保存的响应无法无损恢复。

重新整理已有完整结果的文件前，先预估新增费用并主动点击开始，再选择“使用已有结果”“继续重新整理”或“取消”。确认框有可见的30秒默认继续倒计时；只有已明确授权本次付费时才出现，离线、离开页面、失去焦点、预估过期或规则变化会停止。请勿在确认后离开电脑；继续可能产生新费用。新草稿校验失败时，旧完整版本仍可使用。

完整性检查核对确定性题号列表、类型、章节、小问和来源图形。缺页、遗漏题目、错误来源或相互冲突时不当作完整成功；没有可靠分类依据的题须人工确认检查方式。完成后点“查看结果并保存”，在差异预览中采用，再保存设置；已有人工规则及历史成绩不会静默覆盖。

### 真实批改配置

后端支持 `deepseek-flash` 和 `qwen3.7-flash`。在自己的 Windows 用户环境变量中配置 `DEEPSEEK_API_KEY` 或 `DASHSCOPE_API_KEY`；只有决定开启付费调用时才设置 `AI_ALLOW_PAID=true`，重开终端后启动。`AI_PROVIDER` 保持 `mock`，真实服务在页面弹窗中单独选择。也可参考空凭据的 [.env.example](.env.example) 配置本机 `.env`；不要覆盖已有配置。

**真实批改会将参考与学生 PDF 页面发送给外部服务商，平台不会自动遮盖页面中的姓名、学号。** 请先完成授权与去标识；只改文件名无效。Key 只供后端读取，不放在前端、GitHub Secrets 或公开日志中。

默认每份预算门禁 ¥0.50、每批 ¥2，并发 1；预估达到 ¥0.30 须额外确认。估算不能保证服务商最终账单的绝对上限。连接测试也可能收费，仅主动点击才会请求。

保留自 2.4 引入的输出额度选择、长页/大页的全景与重叠分区，并改善局部放大及失败诊断。`length` 可能表示思考和最终 JSON 耗尽共同额度，须明确调整后重新预估；不自动增额或反复付费重试。DeepSeek 未显式配置时默认 16384、Qwen 默认 8192；弹窗可选 8192 / 16384 / 32768。暂停、取消、重启及未知用量均保留费用保护。

已有少量 DeepSeek 实际使用反馈；发布测试使用合成资料和模拟 API，**没有系统性数学准确率或费用基准，也未重新验证真实账户权限**。具体配置与价格快照见 [API 与费用说明](docs/AI配置与费用说明.md)。

## 数据与更新

数据默认保存在本机 `data/`，包括 SQLite、上传原件、图像缓存、成绩、修订历史和费用账本。`DATA_DIR` 可指定独立位置。先停止服务，再备份完整目录，包括实际存在的 WAL/SHM；备份存放在仓库之外。由 2.4 升级前请先读 [2.8.0 发布说明](docs/releases/v2.8.0.md)，不要覆盖唯一一份数据或用旧版本直接读新版数据。具体操作见使用指南。开发模式和构建模式不要同时操作同一目录。

不要提交 `.env`、`data/`、学生资料、参考答案、名单、成绩、备份或含这些内容的截图。`.gitignore` 不能移除已经提交过的私人文件。更新与旧版兼容注意事项见 [Git 与安全更新](docs/Git版本与安全回退.md)。

学号仅在新上传时自动识别独立的十位数字，保留前导零；歧义留空。点击学生姓名下方的学号或“补填学号”可修改，也可在更多菜单中修改姓名与学号。旧记录不自动补录，同名重传不会覆盖原信息。新增字段不会加入 AI 请求，但 PDF 页面中的身份信息仍须自行处理。CSV 保持“姓名、成绩”两列，成绩如 `9.8` 或 `9.6，漏2题`，不追加“分”。

## 开发与验证

模拟入口默认隐藏，接口默认关闭。仅开发测试时设置 `ENABLE_MOCK_UI=true` 并重启；它独立于付费许可，始终使用本地 Mock。普通助教保持默认关闭；历史模拟结果仍标明身份，不能当作真实 AI 结果。

技术栈：React / TypeScript / Vite、Express、Node.js 内置 SQLite；PDF.js / canvas 本地渲染。开发时用 `npm.cmd run dev`。

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:browser
npm.cmd run test:dev
npm.cmd run test:ai-browser
npm.cmd run test:selection-browser
npm.cmd run test:reliability-browser
npm.cmd run test:pdf-recovery-browser
npm.cmd run test:reference-browser
npm.cmd run test:reference-workflow
npm.cmd run test:assistant-usability
npm.cmd run test:independent-grading
npm.cmd run test:reference-batch
npm.cmd run test:reference-recovery
```

测试只生成合成 PDF/DOCX 和虚构身份，使用隔离数据库及模拟 HTTP，不读取正式数据、不请求真实模型。测试自动创建 `codex输出/codex工作区/` 存放产物。浏览器回归使用本机 Chrome / Edge，可用 `BROWSER_PATH` 指定；测试端口 3108–3113，`test:dev` 含 Windows 独占锁检查。

离线对照可用 `npm.cmd run benchmark:ai -- --template` 生成本机人工标注模板，再用 `--gold` 对照；它只读指定数据，不请求模型。模板及报告包含本机材料信息，不提交 Git。
