# 从v2.8升级到v2.11.0

适用于已有本地数据的v2.8用户，以及试用过2.9/2.10的用户。先完整阅读再操作；如果使用了自己的部署脚本，须核实它实际指定的DATA_DIR。不要仅凭文件夹名称判断数据库位置。

目标是保留旧程序/旧数据，在新副本中验收并切换。源码更新、参考草稿采用和重新批改是不同动作；升级不自动重新计分，也不自动发送付费请求。

## 1. 停止旧服务并备份完整数据

先保存浏览器内未保存的设置或评分，等待学生批改、参考整理及在途模型请求结束；再在运行窗口按Ctrl+C（或使用你自己的安全关闭脚本）。停止所有读写同一DATA_DIR的实例。不要在运行中只复制一个SQLite主文件。

在PowerShell输入实际数据目录，复制到新的时间戳备份；下面使用用户目录变量，不是发布者的个人路径。

```powershell
$oldData = (Resolve-Path -LiteralPath (Read-Host '请输入旧平台实际DATA_DIR的完整路径')).Path
if (!(Test-Path -LiteralPath (Join-Path $oldData 'grading.sqlite'))) { throw '数据库不存在，请重新确认DATA_DIR' }
function Get-DataManifest([string]$root) {
    @(Get-ChildItem -LiteralPath $root -File -Recurse -Force | Sort-Object FullName | ForEach-Object {
        [pscustomobject]@{Path=$_.FullName.Substring($root.Length+1);Bytes=$_.Length;SHA256=(Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash}
    })
}
$backupParent = Join-Path $env:USERPROFILE 'grading-platform-backups'
New-Item -ItemType Directory -Path $backupParent -Force | Out-Null
$backupRoot = Join-Path $backupParent ('before-v2.11-' + (Get-Date -Format 'yyyyMMdd-HHmmssfff'))
if (Test-Path -LiteralPath $backupRoot) { throw '备份目录已存在，不能覆盖' }
$before = Get-DataManifest $oldData
New-Item -ItemType Directory -Path $backupRoot | Out-Null
$backupData = Join-Path $backupRoot 'data'
Copy-Item -LiteralPath $oldData -Destination $backupData -Recurse -Force
$copied = Get-DataManifest $backupData
$after = Get-DataManifest $oldData
$expected = ConvertTo-Json -InputObject $before -Depth 5 -Compress
if ($expected -ne (ConvertTo-Json -InputObject $copied -Depth 5 -Compress) -or $expected -ne (ConvertTo-Json -InputObject $after -Depth 5 -Compress)) { throw '备份核对失败，请保留现场，不能继续升级' }
$before | ConvertTo-Json -Depth 5 | Set-Content -LiteralPath (Join-Path $backupRoot 'files-sha256.json') -Encoding UTF8
```

保留整个备份，包括实际存在的WAL/SHM、uploads、图像缓存、成绩、评分修订、规则版本、调用/费用记录。2.10/2.11的参考任务、草稿及模型最终响应也在数据库中，属于私人材料；不要上传GitHub、群聊或公开网盘。备份不要存进源码仓库。

## 2. 另建新程序和演练副本

继续在同一个PowerShell窗口运行，以保留上一步的路径变量。示例目标已存在时应停止并另选新目录，不能覆盖它。

```powershell
$upgradeRoot = Join-Path $env:USERPROFILE 'grading-platform-v2.11.0'
if (Test-Path -LiteralPath $upgradeRoot) { throw '目标已存在，请选择新的独立目录' }
New-Item -ItemType Directory -Path $upgradeRoot | Out-Null
$newApp = Join-Path $upgradeRoot 'app'
$trialData = Join-Path $upgradeRoot 'rehearsal-data'
git clone --branch v2.11.0 https://github.com/Benhuangsuan/linear-algebra-grading-desk.git $newApp
if ($LASTEXITCODE -ne 0) { throw '源码下载失败' }
Copy-Item -LiteralPath $backupData -Destination $trialData -Recurse -Force
Set-Location -LiteralPath $newApp
npm.cmd ci
if ($LASTEXITCODE -ne 0) { throw '安装失败，停止升级' }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw '构建失败，停止升级' }
$env:DATA_DIR = $trialData
$env:PORT = '3003'
$env:AI_ALLOW_PAID = 'false'
$env:DEEPSEEK_API_KEY = $null
$env:DASHSCOPE_API_KEY = $null
npm.cmd start
```

3003若占用，先确认归属，换一个空闲端口，不随意结束其他进程。浏览器打开对应本机端口。演练阶段不要复制私人.env到新程序；上述环境只作用于本终端，不修改Windows用户或系统配置。按标签安装处于分离HEAD是正常状态。

逐一检查课程/作业、题目规则、独立小问、姓名学号、上传原稿、历史成绩、修订和费用、CSV。参考结果先查看和校对，不急着采用；必须区分“整理完成”“采用到当前清单”“保存设置”。若测试写入，写入的也只会是演练副本，不能回灌正式数据。

遇到缺文件、规则/分数变化、数据库错误或不明差异，停止切换并保留所有副本。不要为了继续而删除旧数据或放宽检查。

## 3. 核对参考草稿恢复规则

- v2.8没有多文件AI任务草稿，升级不会凭空创造模型答案。已上传PDF仍保留，可以主动免费整理或重新预估后使用AI；已有人工题目和历史成绩不自动覆盖。
- 2.10已保存的完整文件草稿，会在读取结果时按文件幂等恢复索引。即使所属整批失败，该文件通过完整性校验后仍可查看、跨任务合并及采用。
- 旧版未保存的失败响应不能从费用账本还原；没有历史内容指纹的旧草稿须对照当前PDF。删除、变更或小节不匹配的材料不能冒用旧草稿。
- 2.11保存的新响应可免费尝试复验；无效、缺题、截断仍不能伪装完整。重试只处理失败文件/尚未验证的分页，但新增请求仍要预估并明确授权。
- 重新整理先保留旧版本，新版本失败不清掉旧完整结果；同号不同内容须选择。已有人工扣分、备注及历史成绩不随草稿变化。
- 已有完整结果再次付费整理，只有本次主动预估并点击开始后才出现30秒默认继续提醒。可使用已有结果或取消；离线、失焦、页面离开、选项/规则/预算失效会停止。确认后不要离开电脑，以免不想要的重复付费。

## 4. 验收后从最终备份创建新正式库

演练结束按Ctrl+C。若期间曾恢复旧服务继续使用，必须再次停止旧服务，并重新执行第1步备份最新数据；更新下面的`$backupData`为该最终备份。不能拿演练开始前的旧快照覆盖期间新增操作。

仍在原窗口且已保留第1步函数和变量时，将最终备份复制到一个不存在的新正式目录（**不是演练副本**）：

```powershell
$newData = Join-Path $upgradeRoot 'data-v2.11.0'
if (Test-Path -LiteralPath $newData) { throw '新正式数据目录已存在，停止以免覆盖' }
Copy-Item -LiteralPath $backupData -Destination $newData -Recurse -Force
if ((ConvertTo-Json -InputObject (Get-DataManifest $newData) -Depth 5 -Compress) -ne (ConvertTo-Json -InputObject (Get-DataManifest $backupData) -Depth 5 -Compress)) { throw '最终正式副本校验失败' }
```

随后关闭演练终端，在**新的PowerShell窗口**进入新app，将DATA_DIR设为上述新正式目录、PORT设为3000，再运行`npm.cmd start`。这使演练的禁费/清空Key设置不会污染日常进程；不要修改原Windows API变量。原先用私人.env配置者，只在本机按原方式为新程序配置自己的.env，不公开、不粘贴密钥到日志。

```powershell
$newApp = Join-Path $env:USERPROFILE 'grading-platform-v2.11.0/app'
$newData = Join-Path $env:USERPROFILE 'grading-platform-v2.11.0/data-v2.11.0'
Set-Location -LiteralPath $newApp
$env:DATA_DIR = $newData
$env:PORT = '3000'
npm.cmd start
```

如另选了安装根目录，请使用自己的实际路径。确认浏览器版本2.11.0及数据位置，复查旧成绩、规则、文件和费用。首次安装/人工评分无需Key；要用AI才保留或设置自己的付费许可。测试连接也可能收费，不是升级必做步骤。

## 5. 回退和后续备份

保留旧程序、旧库和最终备份。新版本若出现严重问题，先停止新服务、备份并保留新数据/日志。没有新业务写入时，可用原程序及原数据恢复旧入口；已经有新上传、评分、规则或费用时，先制定保留新增操作的恢复方案，不能直接丢弃新库。

不要让v2.8程序直接打开被v2.11使用过的数据副本，不用Git强制重置、清理或数据库覆盖完成回退。今后停止服务后备份**实际DATA_DIR**全部内容，路径已经不一定是app内的data/。升级与回退都不自动重算历史成绩或清空费用账本。
