# Git 与安全更新

公开分发版本为 2.11.0（标签 `v2.11.0`）。稳定代码使用 `main`，后续开发使用 `feat/...` 或 `fix/...` 分支；版本标签指向已验收的提交。

## 更新本地安装

从v2.8或中间开发版升级至v2.11.0，请先按[安全升级指南](从v2.8升级到v2.11.md)备份实际完整数据，在新的代码/数据副本验证，再切换。保留旧程序、旧数据库及源码修改，不在唯一数据库上试升级，不用演练库替代最新正式数据。

可用`git status --short --branch`和`git fetch origin`只读核对状态与远程历史；按标签安装处于分离HEAD属正常状态。要维护自己的源码分支，先保留修改，再正常合并/快进，遇到分叉或冲突先处理，不强制覆盖。Git只管理源码，不同步你的课程、参考材料、成绩、费用或.env。

旧结果按原评分快照读取，规则改变不会自动改历史成绩；明确按当前题目重新人工评分须重新录入整份，原记录保留。参考任务的按文件恢复不自动采用或保存，完整规则见[2.11.0说明](releases/v2.11.0.md)。

## 维护分支与版本

从稳定分支创建开发分支，验证后提交变更。在双方历史仍可快进时使用 `git merge --ff-only`；不能快进时先检查差异。公开前审查拟推送的全部历史、文件和标签；只推送审核通过的目标分支与版本标签。

## 回退须同时考虑数据兼容

不要使用 `git reset --hard`、`git clean` 或强推作为普通更新/回退步骤。旧代码可能不兼容新版规则快照与数据。

需要验证旧版本时，另建独立源码目录，复制与该版本兼容的私人备份，并通过 `DATA_DIR` 指向副本；不要让旧版直接读取当前正式目录。先确认备份完整，再决定恢复。停止服务后保存完整 `data/`，包括当时存在的 WAL / SHM，不在运行中只复制单个 SQLite 文件。

本机原始开发历史若含私人文档或路径，不应作为公开发布的历史。独立干净发布仓库应只纳入审核后的源码，不拷贝原 `.git` 或个人数据；保留原仓库供本机追溯。
