# 2.8.0 发布说明

本机使用的线性代数作业批改辅助工具。Windows、Node.js至少24.13.0；在Node.js 24.19.0 / npm 11.17.0验证。不需要数据库软件、Docker、Python或LibreOffice。

## 从2.4以来的主要改进

- 参考答案支持“补充题”等标识，保留大题与小问层级；免费自动整理可结合文字颜色，复杂材料始终可人工校对。选择AI辅助整理须单独授权传输和费用。
- 来源页可添加、更换、移除和预览；“应用调整”更新当前清单，“保存设置”才保存。一题可对应多页，父题图形与小问共享，批改请求包含来源页关系和参考图像。图形使用完整来源页，不承诺任意版面精确裁切。
- 修复拖选文字导致弹窗关闭，统一参考整理入口、字号和操作指引；重要操作不可用时说明原因，普通界面默认隐藏模拟入口。
- 从文件名保守识别十位学号，保留前导零；可人工修改并持久保存，不自动补写旧记录。
- 新人工评分与AI按同一已核对的独立单元计分，避免重复父题扣分。两个独立小问均漏做默认共扣0.4，CSV为 `9.6，漏2题`；普通解答题默认整题，完成性题的实质尝试不因算错扣分。
- CSV仍只有“姓名、成绩”两列，不加“分”；漏题按本次评分快照中的有效独立单元计数。
- 修正multer清单误写2.6.0的问题，恢复与锁文件及已验证实际依赖一致的2.5.0，支持干净 `npm ci`。

## 新用户安装

```powershell
git clone https://github.com/Benhuangsuan/linear-algebra-grading-desk.git
cd linear-algebra-grading-desk
npm.cmd ci
npm.cmd run build
npm.cmd start
```

打开 <http://127.0.0.1:3000>，按Ctrl+C停止；以后在同一目录运行 `npm.cmd start`。初始为空库，人工评分、本地参考整理和数据保存无需API Key。真实AI由使用者配置自己的Key、开启付费许可并在界面逐次授权。

完整步骤：[README](../../README.md)、[助教本地部署与使用指南](../助教本地部署与使用指南.md)、[API与费用说明](../AI配置与费用说明.md)。

## 从2.4升级：先备份，再更新

1. 停止旧服务，确认无正在批改的任务；备份整个实际 `DATA_DIR`（默认 `data/`）到仓库之外，包含数据库、当时存在的WAL/SHM、上传原件、缓存、规则版本、评分修订和费用账本。不能只复制正在写入的SQLite主文件。
2. 保留旧程序和唯一原始数据。Git安装在无未保存源码修改、无分叉时正常更新；ZIP安装在新目录解压、安装、构建，从完整备份创建独立数据副本，不用整个项目覆盖旧目录。
3. 用独立 `DATA_DIR` 和空闲端口检查副本，禁用付费并避免继承生产Key；核对课程/作业、原件、参考页、旧确认成绩、人工修订和账本。新旧程序不能同时写同一库。
4. 旧结果始终按原规则快照读取，不自动拆分旧父题或重新计算成绩；保存新规则也不会自动重批。确需按当前独立小问重新人工评分时，须明确重开已确认成绩并选择对应操作，**重新录入整份评分**；原评分与报告在修订历史保留，不调用AI。
5. 核验后才切换日常入口。异常时停止新实例并保留故障副本；新版本已有新录入时不得直接用旧备份覆盖，应先处理数据衔接。不要用旧代码直接读取当前新版库。

更新命令与恢复边界：[Git与安全更新](../Git版本与安全回退.md)。

## 隐私、人工责任与限制

- 公开仓库只含源码、公开文档和合成测试，不含学生资料、课程答案、成绩库、费用库、密钥或个人部署配置。
- 页面内的姓名、学号不会自动遮盖；只改文件名无效。真实AI会把参考和学生页面发送给外部服务商，使用前须取得适当授权并完成所需去标识。
- 每次作业先独立人工完整批改至少两份代表样本，与AI逐题对照；每份结果都要复核扣分及不确定项，确认后再导出。AI初评不是最终成绩，不能据少量反馈承诺准确率。
- 预算是本机估算门禁，不是服务商账单上限；连接测试也可能收费。参考辅助整理、增大输出额度和重批均须明确授权。
- 复杂公式、颜色约定、多栏、扫描件、极长页和不清晰笔迹可能失败或需人工处理。2.4引入的长页分区、单份重试和费用保护继续保留；不静默删页、不自动升额度付费重试。
- 本次发布验收使用合成数据和模拟API，不执行真实付费请求，不替代各助教的模型质量校准。模拟仅供开发时设置 `ENABLE_MOCK_UI=true`，普通使用保持关闭。

源码与文档采用MIT；第三方依赖遵循各自许可，MIT不授权另行上传的教材、学生作品或个人数据。
