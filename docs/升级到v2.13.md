# 从 v2.8～v2.12 安全升级到 v2.13.0

适用于已有本地数据的 v2.8～v2.12 用户，包括从 v2.11 直接升级。无论原来是用 Git 克隆还是下载 ZIP 解压安装，都可以按本文升级。Git 便于以后更新源码，是推荐方式。ZIP 同样支持，整个流程无需安装 Git。

## 1. 下载新版到独立目录

准备 Node.js 24.13.0 或更新的兼容版本。下面任选一种方式获取固定版本 v2.13.0。新程序须放在旧程序、旧数据和备份目录之外，路径避免方括号 `[` 和 `]`，以便 Windows PowerShell 正确打开目录。

**Git 安装（推荐）**。在 PowerShell 执行以下命令。若目标文件夹已存在，先换一个未使用的目录名。

```powershell
$newApp = Join-Path $env:USERPROFILE 'grading-platform-v2.13.0-app'
if (Test-Path -LiteralPath $newApp) { throw '程序目录已存在，请换一个新目录' }
git clone --branch v2.13.0 https://github.com/Benhuangsuan/linear-algebra-grading-desk.git $newApp
if ($LASTEXITCODE -ne 0) { throw '源码下载失败' }
Set-Location -LiteralPath $newApp
```

按固定标签克隆时，Git 显示 `detached HEAD`（分离 HEAD）属正常现象。以后想用 `git pull` 更新源码，先用 `git status -sb` 检查是否在正确的跟踪分支上。此次升级须先验证旧数据的兼容性，请继续使用独立的新程序和数据副本演练，避免直接 `git pull` 后用新版打开旧库。

**ZIP 安装**。在 [v2.13.0 Release](https://github.com/Benhuangsuan/linear-algebra-grading-desk/releases/tag/v2.13.0) 的 **Assets** 中下载 **Source code (zip)**，解压到新目录。在文件资源管理器打开解压后实际包含 `package.json` 的那一层（可能在外层目录里面），在地址栏输入 `powershell` 并按回车。

## 2. 备份旧数据并在副本中演练

两种安装方式从这里共用步骤。保持 PowerShell 位于新程序的 `package.json` 所在目录，在同一窗口完成备份、演练和正式数据复制。

先保存旧平台的设置和评分，等待批改、参考整理和在途模型请求结束。在旧平台运行窗口按 `Ctrl+C`，或使用原关闭脚本，停止所有读写该目录的实例。启动日志中的“数据保存在”是实际 `DATA_DIR`。也可从原启动脚本或 `.env` 核对；未配置时默认是旧程序目录下的 `data`。

在新程序的 PowerShell 窗口执行备份命令，按提示输入实际 `DATA_DIR` 的完整路径。备份整个目录，避免只复制 `grading.sqlite`。

```powershell
$ErrorActionPreference = 'Stop'
$oldData = (Resolve-Path -LiteralPath (Read-Host '请输入旧平台实际 DATA_DIR 的完整路径').Trim('"')).Path
if (!(Test-Path -LiteralPath (Join-Path $oldData 'grading.sqlite') -PathType Leaf)) { throw '数据库不存在，请重新确认 DATA_DIR' }
function Get-DataManifest([string]$root) {
    @(Get-ChildItem -LiteralPath $root -File -Recurse -Force | Sort-Object FullName | ForEach-Object {
        [pscustomobject]@{Path=$_.FullName.Substring($root.Length+1);Bytes=$_.Length;SHA256=(Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash}
    })
}
$backupParent = Join-Path $env:USERPROFILE 'grading-platform-backups'
if ($backupParent.Equals($oldData, [StringComparison]::OrdinalIgnoreCase) -or $backupParent.StartsWith($oldData.TrimEnd('\') + '\', [StringComparison]::OrdinalIgnoreCase)) { throw '请将备份目录设在旧数据目录之外' }
New-Item -ItemType Directory -Path $backupParent -Force | Out-Null
$backupRoot = Join-Path $backupParent ('before-v2.13-' + (Get-Date -Format 'yyyyMMdd-HHmmssfff'))
if (Test-Path -LiteralPath $backupRoot) { throw '备份目录已存在，不能覆盖' }
$before = Get-DataManifest $oldData
New-Item -ItemType Directory -Path $backupRoot | Out-Null
$backupData = Join-Path $backupRoot 'data'
Copy-Item -LiteralPath $oldData -Destination $backupData -Recurse -Force
$copied = Get-DataManifest $backupData
$after = Get-DataManifest $oldData
$expected = ConvertTo-Json -InputObject $before -Depth 5 -Compress
if ($expected -ne (ConvertTo-Json -InputObject $copied -Depth 5 -Compress) -or $expected -ne (ConvertTo-Json -InputObject $after -Depth 5 -Compress)) { throw '备份核对失败，请保留现场，不能继续升级' }
$expected | Set-Content -LiteralPath (Join-Path $backupRoot 'files-sha256.json') -Encoding UTF8
```

备份包含实际存在的 WAL/SHM、上传原件、缓存、成绩、历史、参考草稿和费用等数据。保留整个备份，放在源码目录之外，仅供本机或私人备份使用。

接着安装、构建并用备份的副本启动演练。演练前不要把私人 `.env` 放进新程序。如需更改 `$upgradeRoot`，请选择旧数据和源码目录之外的新位置。

```powershell
if (!(Test-Path -LiteralPath 'package.json' -PathType Leaf)) { throw '请进入新版 package.json 所在目录' }
$upgradeRoot = Join-Path $env:USERPROFILE 'grading-platform-v2.13.0-data'
if (Test-Path -LiteralPath $upgradeRoot) { throw '目标已存在，请换一个新目录名' }
New-Item -ItemType Directory -Path $upgradeRoot | Out-Null
$trialData = Join-Path $upgradeRoot 'rehearsal-data'
npm.cmd ci
if ($LASTEXITCODE -ne 0) { throw '安装失败，停止升级' }
npm.cmd run build
if ($LASTEXITCODE -ne 0) { throw '构建失败，停止升级' }
Copy-Item -LiteralPath $backupData -Destination $trialData -Recurse -Force
if ((ConvertTo-Json -InputObject (Get-DataManifest $trialData) -Depth 5 -Compress) -ne $expected) { throw '演练副本校验失败' }
$env:DATA_DIR = $trialData
$env:PORT = '3003'
$env:AI_ALLOW_PAID = 'false'
$env:DEEPSEEK_API_KEY = $null
$env:DASHSCOPE_API_KEY = $null
npm.cmd start
```

浏览器打开 <http://127.0.0.1:3003>，确认版本为 2.13.0，终端显示的数据位置为 `rehearsal-data`。若端口占用，在同一窗口把 `$env:PORT` 改为空闲端口，仅重跑 `npm.cmd start`，再打开对应地址。演练的禁费和密钥设置仅作用于当前窗口。

按第 6 节验收。若有缺文件、规则或分数变化、数据库错误等异常，停止切换并保留所有副本。

## 3. 核对参考草稿恢复规则

- v2.8 的原 PDF 会保留，可主动免费整理。v2.10 已保存的完整草稿通过校验后可按文件查看、合并和采用，即使整批失败也一样。
- v2.11 起保存的响应可免费尝试恢复。未保存的响应无法从费用账本还原。旧草稿须对照原 PDF 和对应小节核对，材料已变更时请重新检查。
- 参考草稿需先核对、再采用，最后保存设置。同题号有冲突时逐项选择。重新整理失败时保留旧完整结果，历史成绩和人工记录照常保留。
- 付费重试只处理失败文件或未验证分页，仍需预估并授权。已有结果时，主动预估并点击开始才会出现 30 秒默认继续提醒。可选择使用已有结果或取消。

## 4. 验收后从最终备份创建新正式库

验收通过后按 `Ctrl+C` 停止演练。若期间恢复过旧服务，先再次停止旧服务，在同一窗口重跑第 2 节的备份代码块（从 `$ErrorActionPreference` 开始，到生成 `files-sha256.json` 为止）。`$backupData` 会自动指向最新备份，包含期间新增的操作。

在同一窗口将最新备份复制到新的正式数据目录。此步骤使用 `$backupData`，演练写入留在演练副本中。

```powershell
$newData = Join-Path $upgradeRoot 'data-v2.13.0'
if (Test-Path -LiteralPath $newData) { throw '新正式数据目录已存在，停止以免覆盖' }
Copy-Item -LiteralPath $backupData -Destination $newData -Recurse -Force
if ((ConvertTo-Json -InputObject (Get-DataManifest $newData) -Depth 5 -Compress) -ne $expected) { throw '最终正式副本校验失败' }
Write-Host "新正式数据目录：$newData"
```

记下命令输出的新正式数据路径。确认旧服务已停止，关闭演练窗口，从新版 `package.json` 所在目录**重新打开 PowerShell**，避免沿用演练设置。若原来用私人 `.env` 配置 AI，可在本机为新程序按原方式配置，密钥请妥善保管。

```powershell
if (!(Test-Path -LiteralPath 'package.json' -PathType Leaf)) { throw '请进入新版 package.json 所在目录' }
$newData = (Resolve-Path -LiteralPath (Read-Host '请输入新正式数据目录').Trim('"') -ErrorAction Stop).Path
if (!(Test-Path -LiteralPath (Join-Path $newData 'grading.sqlite') -PathType Leaf)) { throw '请核对新正式数据目录' }
$env:DATA_DIR = $newData
$env:PORT = '3000'
npm.cmd start
```

打开 <http://127.0.0.1:3000>，确认浏览器显示 **2.13.0**、终端显示新正式数据目录，再复查成绩、规则、文件和费用。以后重开平台时也从新版目录执行上面的启动命令，输入同一个新正式数据路径。升级验收可全程使用人工评分和免费功能。

## 5. 回退和后续备份

保留旧程序、旧库和最终备份。新版本若出现严重问题，先停止新服务、备份并保留新数据/日志。没有新业务写入时，可用原程序及原数据恢复旧入口；已经有新上传、评分、规则或费用时，先制定保留新增操作的恢复方案，不能直接丢弃新库。

新旧版本始终使用各自的 `DATA_DIR`，避免旧程序打开新版数据。回退时保留原目录，避免 Git 强制重置、清理或覆盖数据库。以后仍应先停止服务，再备份**实际 `DATA_DIR`** 的全部内容。升级与回退都保留历史成绩和费用账本。

## 6. v2.13 兼容性与验收清单

- 对照旧版核对课程、作业、学生、原件、规则、成绩、修订、参考草稿、费用及 CSV。升级保留历史数据，无需重评或补填备注。
- 用合成材料混选正常与损坏文件。保存题目和规则后进行免费快速检查，移出问题文件，其余通过者无需重扫。材料或设置变更后重新检查。每份和整批预算继续生效，新增付费请求仍需授权。
- 免费查看“解释这项扣分”。用合成作业验证正确题可保存、刷新和删除“助教备注（不扣分）”，成绩和 CSV 保持一致。其他判定编辑“扣分原因”。AI 追问需单独确认传输和费用，解释供人工复核。演练可跳过付费功能。
- 单份上传上限仍为 30 MiB、1～100 页。v2.12 起已保存且匹配的成功分批可续跑，v2.11 的整份失败记录没有这类续跑证据。
