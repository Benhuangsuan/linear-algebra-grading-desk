# 线性代数与几何作业批改平台：助教本地部署与使用指南

> 适用程序：**2.8.0**（Windows 本机部署）。本指南供课程助教使用。程序是辅助评分工具，**AI 给出的结果不是课程最终成绩，必须由助教复核并确认**。本项目不是学校统一部署的教学平台。
>
> **首次使用推荐顺序**：安装 Node.js → 下载项目源码 → 安装依赖并构建 → 启动平台（可先用人工评分）→ 按需配置自己的 API Key → 创建课程与作业 → 上传参考答案 PDF 并核对题目/小问 → 上传学生 PDF → 先与人工批改结果对照 → 再批改其余学生 → 人工审核扣分点 → 确认并导出成绩。

## 1. 先理解平台能做什么

- 所有课程、作业、上传的 PDF、成绩和人工修订记录默认保存在**自己的电脑**里，浏览器通过 `http://127.0.0.1:3000` 访问本机服务，不需要服务器、域名、云数据库、Docker、Python 或 LibreOffice。
- AI 批改使用 DeepSeek Flash 或 Qwen 视觉模型（请以实际平台可选服务为准）。**使用云端模型时，作业及参考答案的页面图像会发送到外部服务商**，且可能产生按 token 计费的费用；仅 Mock/人工评分可以不配置 API。
- 保留「学生作业」「作业设置」两个主要页面。可按姓名搜索，筛选“未批改”等状态，勾选指定学生批改。**正确题默认不展示长篇反馈**，主要展示扣分和待复核项目。
- 同一次作业可以批量上传学生 PDF，保存 AI 建议、人工调整、最终确认、历史记录，导出“姓名”“成绩”两列 CSV。
- 这是 2.6.0 对应的说明；具体按钮名称可能随以后版本更新，应以项目最新 README 为准。

## 2. 从零安装（每位助教在自己电脑操作）

### 第一步：安装 Node.js 与 Git

1. 在 Windows 安装 **Node.js 24.13.0 或更新的兼容版本**（2.5.0 已在 Node.js 24.19.0 / npm 11.17.0 验证）。从 Node.js 官方网站下载安装。安装过程一般会同时安装 npm。
2. 为方便后续更新，建议安装 Git for Windows。也可以不安装 Git，在 GitHub 仓库网页选择 `Code → Download ZIP` 下载源码并解压；但以后更新不如 `git pull` 方便。
3. 打开 PowerShell，检查：

   ```powershell
   node -v
   npm.cmd -v
   git --version
   ```

   如果采用 ZIP 方式，第三行可跳过。若 `node` 找不到，关闭旧终端并重新打开；必要时重启电脑。

### 第二步：下载项目

- 项目仓库：**[Benhuangsuan/linear-algebra-grading-desk](https://github.com/Benhuangsuan/linear-algebra-grading-desk)**。
- 有 Git 的情况下，在你想存放项目的文件夹运行：

  ```powershell
  git clone https://github.com/Benhuangsuan/linear-algebra-grading-desk.git
  cd linear-algebra-grading-desk
  ```

- 使用 ZIP 下载的，解压后在文件夹空白处打开 PowerShell，确认终端所在目录含 `package.json`。
- **无需复制发布者电脑上的 `data/`、学生 PDF、参考答案或 API Key**。每位助教都应在自己的设备上建立独立的数据与模型账户配置。
- 如果仓库是 Private，你必须先收到仓库拥有者的 GitHub 访问邀请并接受；下载或 clone 时可能需要登录 GitHub。

### 第三步：安装依赖并构建

在项目根目录执行：

```powershell
npm.cmd ci
npm.cmd run build
```

- `npm.cmd ci` 会依据 `package-lock.json` 下载程序依赖，第一次需要联网；不要手工逐个下载第三方包。
- `npm.cmd run build` 构建本机使用的前后端程序。完成后可启动：

  ```powershell
  npm.cmd start
  ```

- 浏览器打开 **<http://127.0.0.1:3000>**。保持 PowerShell 窗口运行；按 `Ctrl+C` 停止服务。重启电脑后，只需回到项目目录重新执行 `npm.cmd start`，已保存的数据仍在。
- 只有开发/修改源码时才需要 `npm.cmd run dev`；日常使用建议采用 `build` + `start`。**不要同时运行 `dev` 与 `start` 操作相同的数据目录。** 不能通过双击 `dist/index.html` 启动完整系统。
- 本服务默认仅监听本机 `127.0.0.1`，其他设备不能直接访问；它不是已上线的网页。

## 3. 配置自己的 AI 模型账号（只需首次设置，按需充值）

### DeepSeek（优先作为入门示例）

1. 自行登录 [DeepSeek API 平台](https://platform.deepseek.com/) 创建 API Key，按服务商规则开通余额和计费。**创建 Key 与实际消费是两回事**；调用接口通常根据用量收费，余额不足时可能失败。
2. 在 Windows 开始菜单搜索 **“编辑账户的环境变量”**，进入“用户变量”，新建：

   | 变量名 | 变量值 |
   | --- | --- |
   | `DEEPSEEK_API_KEY` | 你自己创建的真实密钥 |
   | `AI_ALLOW_PAID` | `true`（只在你同意开启真实付费调用后设置） |

3. 关闭原 PowerShell 窗口再重新打开；如果使用 VS Code 内置终端，通常需要重启 VS Code，让新环境变量被读取。**切勿将 Key 粘贴到课程聊天群、GitHub、前端代码或 README 里。**
4. 启动程序，在「学生作业」选中一份作业，打开「AI 批改已选」，选择 DeepSeek，应能看到已检测到配置；主动点击「测试连接」会发送**合成测试图片**，可能产生少量费用。连接成功不等于数学批改准确性已得到验证。
5. 默认 `AI_PROVIDER` 保持 `mock`；**界面里单独选择真实模型**。不要为了调用 DeepSeek 随意把后端默认模式改成其他名称。

### Qwen（可选）

使用阿里云百炼时，自行申请对应区域的 Key，配置 `DASHSCOPE_API_KEY`。需要确保平台选择的 Qwen 模型、服务端点与 Key 所属区域一致。首次使用建议先只开通一个模型，避免多服务商同时产生费用。

### 如果不使用 AI

可跳过 API 配置，仍然使用课程管理、PDF 上传和纯人工评分。普通界面默认隐藏模拟入口；历史模拟结果会明确标注，不代表数学正确性。

## 4. 每次新作业的标准操作流程

### A. 创建课程与作业

1. 在左侧创建课程，例如“线性代数与几何·2026秋”；然后创建本次作业，例如 `HW5`，填写覆盖小节（如 `2.9, 3.1`）。
2. 进入 **「作业设置」**，填写本次作业总分、具体作业范围及课程评分规定。不要直接套用以前作业中的分值和题号，而不核对教师本次要求。

### B. 上传参考答案 PDF，核对题目与扣分单元（这一步非常重要）

1. 先在本机把本次作业**原题及参考答案导出为 PDF**，再上传到作业设置中；优先保证包含数学公式、矩阵、每小问判定及解释的页面清晰、完整。程序仍可以保留 DOCX，但**云端视觉批改只发送 PDF 页面**。
2. 点击 **「整理题目清单」**，检查平台整理出的题目，选择要添加的内容。检查范围与题目数量；PDF 排版可能导致识别不全，扫描 PDF 可能无法自动整理，需要人工补录。
3. 在「查看题目与调整个别规则」中逐题核对。**大题与小问不是同级关系**：判断题有 a/b/c，应在该父题下展开/补齐小问，而不是把 `24/a` 当作新的并列大题。
4. 判断题每个独立命题是一个扣分单元；解答题通常整题一个单元，只有互相独立的小题才设置“各小题独立扣分”。仅需检查完成的题目可能在参考答案中只有**题号**，此时只核对是否有学生作答，不要要求模型虚构题干或判断正确性。
5. 若新提取或调整小问，打开父题右侧「调整」，确认 a/b/... 编号及题干、参考解（有时程序可能分错这两个字段），勾选「已核对全部小问」→「应用调整」→ 回到作业设置点「保存设置」。**题目清单看起来齐全，不代表小问已完成校对**；若 AI 弹窗显示零个单元或不允许估价，首先检查这一步。
6. 如重新整理参考答案出现差异弹窗，先检查当前、新增和已有题目的数量；选择“暂不添加，保持现有题目”或“添加新发现的题目（推荐）”。已有内容只有勾选后才会替换，添加后仍需保存设置。

### C. 明确评分口径（以下为可调整的默认规则）

| 扣分单元情况 | 常用处理 |
| --- | --- |
| 未做 / 未检索到作答 | 暂扣 **0.2 分**，之后必须由助教核查；AI 未找到不必然等于真正漏做 |
| 有作答但回答错误 | 扣 **0.1 分**，应简要说明错在哪里 |
| 判断题 | 每个独立命题分别计分；识别中文“对/错”、√/×、T/F 等表达 |
| 普通计算/证明解答题 | 默认整题一个单元；部分做了但答案不完整/错误通常按做错处理，不按整题漏做 |
| 仅检查完成 | 只要存在可辨认的实质尝试，即使只做了一部分或算错也算完成，不因正确性扣分 |
| 合理等价解法 | 应接受不同但正确的数学表达与证明方法，不能因为过程与参考答案不同就扣分 |

具体规则最终以本次课程负责教师要求和已保存设置为准；本平台常用满分为 10 分，但不得把该值当作所有课程的普遍标准。

### D. 上传学生 PDF

1. 在「学生作业」点击「上传作业」，支持一次批量上传，**最多 50 份/次、单份最多 30 MB、1～100 页**；不接受加密 PDF。
2. 推荐文件名 `线代作业5-姓名-学号.pdf` 或 `学号_姓名.pdf`；学号可以按课程要求省略。系统支持连字符、空格、加号及合理混用，学号只自动填写明确的十位数字并保留前导零，歧义留空。点击姓名下方的学号或“补填学号”可修改，允许清空；保存后刷新、重启和重新批改仍保留。旧记录不自动补录，同名上传保留原记录。**仍需人工核对，不能完全依赖识别**。
3. 检查学生 PDF 内的内容是否完整可见。如果 PDF 页上包含姓名、学号等身份信息，必须先在本机做真实去标识处理，或按课程授权及适用隐私要求选择合规流程；**平台不会自动遮盖手写身份信息**。仅修改文件名不能去掉页面里的姓名。
4. 不要向公开 GitHub 仓库上传这些 PDF、学生名单或结果 CSV。

### E. 先校准，再批改全班：每次作业必须做

**至少先选取 2 份具有代表性的学生作业，由助教亲自完整批改，再让 AI 批改同样的 2 份并逐题对照。** 最好涵盖较正确和有明显错误、文字判断和矩阵/证明等不同题型。不能仅比较总分——同分也可能是错扣与漏扣相互抵消。

1. 在“未批改”等筛选中只勾选选定的 2 份，打开「AI 批改已选（2）」；核对弹窗中的学生、PDF 文件名以及实际扣分单元列表。
2. 选择模型，核对每份预算上限、本批预算及「批改选项」；DeepSeek 2.4 未另设时默认输出额度 16384，弹窗可以对本次选择 8192 / 16384 / 32768。
3. 按界面逐项确认评分单元、PDF 已符合去标识要求、同意发送资料和可能费用；点击 **「预估费用」**，确认预估人数、页面/图像数和预算，再点击 **「开始真实批改」**。单份默认预算门槛 ¥0.50、批次默认 ¥2、预计达到 ¥0.30 时额外确认，**本地门槛不是服务商账单的绝对上限**。
4. 对照人工批改记录，检查：漏题是否误报、判断题符号是否读对、解答题是否接受等价解法、计算/证明错误是否真错、扣分单元是否正确、证据页码是否准确。
5. 发现偏差先区分**评分规则问题**与**模型识别/判断错误**：全班通用的规则确需调整时，先修改本次作业设置并保存版本；不要把某位同学偶然的错误写成全班通用规则。已有结果使用旧快照，不会自动按新规则重批；是否付费重新批改须明确决定。
6. 如果两份测试样本不足以确认质量（如字迹模糊、题型复杂、出现误扣/漏判），增加人工完整批改的样本，直到有足够信心再扩大范围。

按钮附近会显示当前不能继续的原因，优先提示一至两项，其余可展开。未核对小问时，点击“前往作业设置”，在“题目清单与扣分规则”完成校对、应用调整并保存，再返回列表重新选择学生。修改选择、规则、预算或授权会使旧预估失效，须重新预估；不应反复点击开始按钮。

### F. 对剩余作业进行 AI 批改，并人工审核扣分

1. 在「未批改」筛选选择剩余需要处理的学生。**已完成 AI 初评的学生默认不再参与普通选择**，避免重复付费。一次可以只选若干份，不必一次全部批改。
2. 先核对真实选中的人数和目标，完成预算预估，再开始批改。切换学生、参考材料、规则或输出额度后必须**重新预估**，不能套用旧的费用授权。
3. 批改结束后，**至少逐条检查每位学生的全部扣分项（包括 −0.1 和 −0.2）**：打开原稿证据页，核对错误理由；尤其是 −0.2“未检索到”必须由助教检查是否真的漏做。AI 可能比人更严格，**不能直接将全部 AI 扣分原样接受**。
4. 正确题默认隐藏，可以提高日常效率；但它们的隐藏**不表示已被证明绝对正确**。如果模型曾出现漏判，或遇到新型题目/异常作业，应增加正确题抽查或整份复核。
5. 修改错误判定、扣分、说明或证据页后保存；有关键不确定项时按界面要求逐项核实，最后点击确认成绩。确认后已有结果受保护，需明确重开审核才能修改。
6. 从列表导出两列 CSV（姓名、成绩）；未确认的行可能显示“待确认”，不要直接用于最终成绩上报。成绩只写数值，如 `9.8`；存在最终漏做扣分时写 `9.6，漏2题`，不加“分”。漏题按现有独立扣分口径计数，答错不算漏做；不增加学号列。检查是否有姓名识别异常或重复文件。

## 5. 失败与重批如何处理

- **一批中只有某份失败**：不要重新批改已成功的学生。在失败行使用「AI 重试」，或在「批次与费用」里选择“仅重试此份”；重新确认授权并预估费用。失败的请求仍可能产生 token 费用。
- **提示 `length` / `output_limit`**：模型的总输出额度（包括思考 token 和最后的 JSON）已耗尽，**并不等于 PDF 读取失败**。2.4 提供“批改选项”可把本次额度由 8192 提高到 16384，必要时 32768，**先重新预估**。额度提高可能增加预算；不要无限重复相同设置、也不保证提升就一定成功。
- **非常长的单页 / 非 A4 作业**：2.4 会对长页生成全景和重叠分区，仍保持原 PDF 页码。若提示请求太大或超过图像限制，先按界面说明在本机重新导出合理的 PDF，确保**所有题目都保留且清晰**；不要只删掉难识别页面来省钱。
- **“AI 批改”按钮不能点击 / 单元为 0**：先看是否勾选目标学生，是否逐命题核对并保存题目清单，是否配置 Key/`AI_ALLOW_PAID`，是否完成三个确认框与费用预估；不要一开始就认为模型或网络出错。
- **Mock / 手工稿 / 确认状态**：Mock 是演示；已有正式 AI/人工结果要通过明确“重新 AI 批改”入口，不应被重复批改自动覆盖。已确认成绩需按界面重开审核。
- **连接失败**：检查 Key 是否属于正确服务商/区域、是否有余额及网络是否可访问；重启终端继承环境变量。不要在日志或截图里公开 Key。

## 6. 费用、隐私与数据备份

### 费用

- API Key 本身不是免费无限调用的凭证，通常按输入图片/文本、模型输出等实际用量计费。价格可能调整，不要直接套用其他助教的一次批改费用。
- 参考答案/规则重用、缓存、已完成结果复用可以减少重复成本；是否命中云端缓存，以服务商返回 usage 为准，不能保证命中。
- 平台的费用显示可能是估算，尤其遇到取消、超时、usage 未返回时。定期在服务商控制台对照实际消费。无需为了试用多次自动重批已完成作业。

### 隐私

- 程序与本地 `data/` 只在自己的电脑；**一旦点击真实 AI 批改，参考 PDF 和学生作业的页面图像将离开本机**。使用前须根据课程负责人要求和有关规定确定适当授权与数据处理方式。
- 平台不会自动涂抹页面中姓名学号；给云端使用的材料必须按要求预先处理。文件名即使有姓名，程序设计不会主动把它作为 API 字段发送，但页面内部若有身份信息仍可能传给服务商。
- 不在 GitHub、课程群或公开网盘分享 `data/`、API 密钥、真实参考答案及学生批改结果。未经明确许可也不要发布教材页面、作业参考答案或教师批改记录。

### 备份与恢复

所有课程、上传资料、成绩、历史及缓存默认位于项目根目录的 `data/`，包括 `data/grading.sqlite`、`data/uploads/`、`data/ai-cache/` 等。

**先 Ctrl+C 停止服务**，再在项目根目录备份：

```powershell
$backupRoot = Join-Path $env:USERPROFILE 'grading-platform-backups'
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
$backupName = 'data-backup-' + (Get-Date -Format 'yyyyMMdd-HHmm')
Copy-Item -LiteralPath '.\data' -Destination (Join-Path $backupRoot $backupName) -Recurse
```

上述命令将备份保存在当前 Windows 用户主目录下、**项目仓库之外**的 `grading-platform-backups` 文件夹。建议进一步保存在安全的私人备份位置，不要加入 Git 或公开分享。恢复前停止程序并先备份当前版本的数据；不要在数据库正在写入时只复制单个 `.sqlite` 文件，也不要让旧版本程序直接读取已被新版本更新的数据库。

## 7. 以后如何更新程序

- 每位助教的数据各自在自己的电脑，更新源码时**不要删除或覆盖 `data/` 和自己的环境变量**。
- 使用 Git 下载的用户，可在项目根目录确认没有自己改动过的源码后，按发布者通知的稳定版本更新，例如：

  ```powershell
  git status
  git pull --ff-only
  npm.cmd ci
  npm.cmd run build
  npm.cmd start
  ```

- 更新前先停止服务并备份 `data/`；如果改动源码或工作区不干净，先保存自己的修改，不要 `git reset --hard` 或 `git clean`。如果后续版本发生数据库兼容变化，请优先阅读对应发布说明。
- ZIP 用户以后可以下载新版本 ZIP，另建新目录，按维护者说明迁移个人 `data/`；**不要用整个新项目文件夹覆盖原文件夹**。
